— comemory · architecture

Two layers, one file.

A memory layer of markdown and a code layer of extracted symbols, joined by typed edges in one SQLite file, queried by a pipeline that never calls a model.

Every deck below is a set of cards. Select one and the panel under it reads that card's facts; in the capabilities deck the other cards also tell you whether they use the selection or are used by it. Arrow keys move between cards. The prose version of all of it is docs/architecture.md, which stays the authoritative reference.

— §01 · layers

Delivery on top, storage at the bottom.

Six top-level folders under src/, and guardrails.config.json allows no seventh. The two delivery adapters parse input and render output; the capabilities do the work; the store is the only module that may import rusqlite. Edges here are import edges, as ast-grep finds them in the tree today.

— §02 · capabilities

Ten capabilities, one directed table.

Each folder under src/domains/ owns one area of behavior end to end: its models, its algorithms, and the command cores both the CLI and the HTTP server call. A capability may depend on another only through the 27 edges declared in scripts/architecture-policy.json; scripts/architecture-check.sh fails any other.

— §03 · retrieval

Route, expand, rerank, diversify.

A query runs entirely in Rust. Three candidate legs are fused by reciprocal rank fusion, five multiplicative priors reorder the pool, near-duplicates collapse, and the page is cut from a bounded window so deeper pages do not drift. search-code runs the same shape over symbols with its own four priors.

— §04 · storage

Markdown is the truth, SQLite is the index.

One directory holds everything. The markdown files are the source of truth; comemory.db is a mirror that comemory rebuild reconstructs from them, carrying across what markdown cannot rebuild: the code index, the document index and the learning-loop tables. 

~/.comemory/
├── memories/{id}-{slug}.md      ← source of truth (markdown + frontmatter)
├── memories/.trash/{id}.md      ← soft-deleted, retained 30 days
├── comemory.db                  ← one SQLite file: FTS5 · sqlite-vec · edges
└── config.toml                  ← per-user configuration

— §05 · write paths

Two write paths, one seam for derived state.

A save writes markdown first and mirrors it second; an index run walks the tree, extracts symbols, mines the graph and materializes PageRank. Both end by refreshing the two derived artifacts, the memory-graph rank and the edge_fts triplet index, through one best-effort pass that runs only after the primary transaction has committed.

comemory save "…" --kind decision

  1. Parse and identify

    Build the memory; id = sha256(body)[:8], content_hash the full digest. Equal bodies can never disagree on either.

  2. Prior lookup, before the database opens

    A live or trashed file with this id and a different hash is a 32-bit collision: refused, nothing written. A matching prior keeps its created and answers created: false.

  3. Vector guard and near-duplicate check

    A supplied vector must match the locked dimension. SimHash scans live rows; a near-duplicate is reported as duplicate_of and the save proceeds.

  4. Atomic markdown write

    memories/.{id}.tmp renamed to memories/{id}-{slug}.md. A same-body re-save lands on the same filename; a trashed copy is purged.

  5. One SQLite transaction

    The memories row, its memory_fts row, the memory_vec row when a vector came, and the reference edges derived before the write.

  6. Refresh derived state

    Memory PageRank and edge_fts, best effort, after commit. If the mirror fails the markdown is kept and the error names the path and comemory rebuild.

comemory index-code --repo r --path .

  1. Walk the working tree

    Respecting .gitignore, grouping files by language: Rust, TypeScript, JavaScript, Python, Go.

  2. Skip what is already ingested

    Each path's git blob OID is compared with repo_marker; an unchanged blob is not re-read.

  3. Extract symbols with ast-grep

    Oversized symbols split into child chunks at AST boundaries, pointing at their parent through code_symbols.parent_id.

  4. Upsert per file

    code_symbols and code_fts rows in one transaction per file.

  5. Mine the code graph

    co_changed edges from windowed git history with a mega-commit guard and a last_mined_commit cursor; imports edges from per-language import resolution.

  6. Materialize PageRank and reward

    Weighted PageRank lands in code_symbols.rank_score. Commit co-activation pays a triple-channel reward to each memory that references a touched file, then the cursor advances to HEAD.

— §06 · the edge graph

Edges are rows, walks are recursive queries.

The edges table is a flat (src_kind, src_id, edge_kind, dst_kind, dst_id, weight) row set that replaced the v0.1 graph database. Multi-hop traversal is a SQLite recursive common table expression, and two PageRank passes are materialized from it rather than computed at query time.

edge kinds

  • supersedes
  • conflicts_with
  • relates_to
  • derived_from
  • references_file
  • references_symbol
  • references_document
  • in_repo
  • authored_by
  • tagged
  • co_changed
  • imports
  • co_activated
memory rank
PageRank over direct memory relations plus co-citation of the same file or symbol, written to memories.rank_score. Hub kinds in_repo, authored_by, tagged are excluded.
code rank
Weighted PageRank over co_changed and imports, written to code_symbols.rank_score on every index-code.
expansion
The top 8 provisional hits seed one undirected walk of depth 2 over an allowlist of kinds; what it finds joins the fusion as a third list, tier 0.
reward
A commit that touches a file a memory references pays a co_activated edge, an activation bump, and once, at weight 2, a confidence-gated used event with its provenance recorded.
edge_fts
A derived triplet index, src —rel→ dst as searchable text, rebuilt in one ordered statement rather than written through. Backs comemory edges.

— §07 · gates

The tree is a config, not a habit.

comemory follows the toolu-conventions Rust stack, with stricter local ceilings. Each rule has exactly one enforcer, and scripts/check-all.sh runs all of them before a push and again in CI.

  1. 01No barrelsA module that grows into a folder keeps its file beside it; mod.rs is banned. A file of only pub use lines is a barrel.no-barrels✓
  2. 02Size ceilings300 code lines per file under src/, tests exempt, and 100 lines per function. Both declared once in guardrails.config.json.file-size · too_many_lines✓
  3. 03Zero warnings, no silencingClippy over all targets and features with -D warnings, and no #[allow] in production code.lint-check✓
  4. 04The store chokepointNo production file outside src/store/ may import rusqlite, and no store function returns a driver cursor. A two-sided ratchet.store-chokepoint-check✓
  5. 05The dependency tableCapability-to-capability imports must appear in architecture-policy.json; an empty domain scaffold fails too.architecture-check✓
  6. 06Shipped migrations are frozenEvery released migrations/*.sql must stay byte-identical to its content at the first tag that shipped it.migration-check✓
